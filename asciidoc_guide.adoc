Copy sections from here into new docs as needed.

== 1. Basic Document Structure

Use this as a starter template:

[source,adoc]
----
= Document Title
Author Name
:toc:
:sectnums:

== Overview
Short summary.

== Details
Main content.
----

== 4. Source Code Blocks

=== Rust Example

[source,rust]
----
fn add(a: i32, b: i32) -> i32 {
		a + b
}

fn main() {
		println!("{}", add(2, 3));
}
----

----

== 5. Admonitions (Notes, Warnings, Tips)

Use admonitions to highlight important information.

[source,adoc]
----
NOTE: This is a note.
TIP: Use short examples that can be copied quickly.
WARNING: Keep command examples aligned with current tooling.
CAUTION: Avoid outdated CLI flags.
IMPORTANT: Validate docs after changing CI commands.
----

NOTE: This is a note.

TIP: Use short examples that can be copied quickly.

WARNING: Keep command examples aligned with current tooling.

== 9. Include Reusable Content

Use includes for shared snippets.

[source,adoc]
----
include\::docs/shared/ci-commands.adoc[]
----

You can also include tagged regions from another file:

[source,adoc]
----
include\::docs/shared/setup.adoc[tag=macos]
----

== 11. Developer Documentation Templates

=== API Section Template

[source,adoc]
....
== API: Feature Name

=== Endpoint
`GET /api/example`

=== Request
[source,json]
----
{ "id": 1 }
----

=== Response
[source,json]
----
{ "ok": true }
----

=== Errors
|===
|Code |Meaning
|400 |Invalid input
|500 |Server error
|===
....

=== Runbook Template

[source,adoc]
----
== Runbook: Task Name

=== Purpose
Why this task exists.

=== Preconditions
* Access required
* Tooling installed

=== Steps
. Run command A
. Validate output B
. Roll back if C happens

=== Verification
How to confirm success.

=== Rollback
How to undo safely.
----

== 12. Best Practices

* Keep sections short and scannable.
* Prefer runnable commands over pseudo commands.
* Keep examples synchronized with the repository state.
* Use one top-level topic per document.
* Add a short "Verification" section for operational docs.

* [ ] Links resolve correctly.
* [ ] Code blocks use correct language hints.
* [ ] Headings are consistent.
* [ ] Outdated references were removed.
